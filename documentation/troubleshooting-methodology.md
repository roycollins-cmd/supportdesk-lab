# IT Troubleshooting Methodology 

## Objective 

This document defines the standard troubleshooting process used in the SupportDesk Lab.

## 1. Identify the problem 

Determine exactly what the user is experiencing. 

Questions may include:

- what happened? 
- when did the problem start 
- what changed recently 
- is the problem affecting one user or multiple users? 
- is there an error message? 

## 2. Gather Information 

Collect relevant technical information. 

Examples: 

- computer name 
- username 
- operating system 
- IP address 
- application involved 
- error message 
- recent changes 

## 3. Reproduce the problem 

attempt to reproduce the issue when possible. 

## 4. Diagnose 

Determine the likely root cause. 

Possible causes inlcude: 

- hardware failure 
- software configuration 
- network connectivity 
- user permissions 
- authentication 
- DNS 
- operating system problems 
- security issues 

## 5. Apply the solution 

Make the appropriate change while minimising disruption to the user. 

## 6. Verify 

Confirm that the problem has been resolved. 

The user should also confirm that the expected functionality has returned. 

## 7. Document 

Record the folling information: 

- problem 
- symptoms 
- diagnosis
- root cause 
- resolution 
- verification 
- preventative action 

## 8. Escalate when necessary 

Issues should be escalated when they exceed the technician's access, knowledge, authorisation, or scope.
